# Чеклист сдачи проекта Hotel Booking

## 1) Функциональность
- [ ] Регистрация и авторизация (JWT) работают.
- [ ] USER может создавать/просматривать/отменять только свои бронирования.
- [ ] ADMIN может управлять пользователями, отелями и номерами.
- [ ] Доступные номера возвращаются корректно по датам.
- [ ] Рекомендации сортируются: `times_booked ASC`, при равенстве `id ASC`.

## 2) Согласованность между сервисами
- [ ] При создании брони сохраняется `PENDING`.
- [ ] После успешного `confirm-availability` статус меняется на `CONFIRMED`.
- [ ] При ошибке/тайм-ауте статус становится `CANCELLED`.
- [ ] Выполняется компенсация `release` при частичном успехе.
- [ ] Вызовы в Hotel Service с timeout/retry/backoff.
- [ ] Повтор доставки того же запроса не создаёт дублей (idempotency key/requestId).

## 3) Безопасность
- [ ] JWT TTL = 1 час.
- [ ] Resource Server настроен в Booking и Hotel сервисах.
- [ ] Роли `USER`/`ADMIN` проверяются на endpoint/методном уровне.
- [ ] Корректные коды ошибок: 401/403.

## 4) Надёжность и конкурентность
- [ ] Нет гонок данных при конкурентном бронировании одного номера на пересекающиеся даты.
- [ ] Конфликт возвращает `409` (или документированный эквивалент).
- [ ] Операции confirm/release идемпотентны.

## 5) Тестирование
- [ ] Unit + integration тесты ключевой логики.
- [ ] Позитивный сценарий бронирования.
- [ ] Негативный сценарий: недоступен Hotel Service.
- [ ] Негативный сценарий: timeout + retries + компенсация.
- [ ] Сценарий повторной доставки того же requestId.
- [ ] Тесты авторизации и ролей.

## 6) Документация
- [ ] README с инструкцией запуска.
- [ ] Описание endpoint-ов по сервисам.
- [ ] Swagger/OpenAPI доступен.
- [ ] Описаны архитектура и ключевые решения.

## 7) Предзаполнение данных
- [ ] Есть seed-данные (админ, несколько отелей/номеров, тестовые пользователи).
- [ ] Данные позволяют продемонстрировать рекомендации и сценарии бронирования.

## 8) Логирование и трассировка
- [ ] Логируются ключевые шаги с `bookingId/requestId`.
- [ ] В логах видны переходы состояний и результат компенсации.
- [ ] Добавлен traceId (через MDC/observability).
